## 2. Что такое MotionBricks (проверено по репозиторию и карточке модели)

* Модель достраивает движение между **4 последними позами (контекст)** и **1–4 целевыми позами**, 30 Гц. Одна генерация даёт 6–16 токенов по 4 позы = 0,6–1,9 с; движение получается цепочкой генераций (рантайм проигрывает, записывает, берёт последние 4 позы как новый контекст).
* **Целевые позы задаёт приложение.** Ходьба/бег — это не «команда», а позы-цели, расставленные впереди персонажа с нужной скоростью. Присед, прыжок, взаимодействия — «Smart Primitives» (набор целевых поз вокруг объекта), без дообучения.
* Модель SOMA: **30 суставов**, ~200 млн параметров, ONNX opset 17, FP32 (758 МБ) и mixed FP16 (380 МБ), batch N≥1. Вход — 7 тензоров, выход — `[N,64,366]` (позиция корня, позиции суставов, 6D-вращения, скорости, контакты стоп).
* Рантайм: Python 3.12, **TensorRT 10.8 (`tensorrt-cu12`)**, NVIDIA Warp, Newton (вьюер), usd-core. Генерация одного запроса на RTX 4090: 2,5 мс FP32 / 1,3 мс FP16.
* Есть «движок» ONNX без TensorRT (ONNX Runtime), но пред/постобработка (координаты, коррекция конца, обрезка граничных кадров) живёт в Python-движках.

## 3. Что игроку реально покажет анимация тела (важно для приоритетов)

Вид только от первого лица: тело скрыто (голова масштабируется в ноль, рюкзак и ремни убраны), у вьюмодели видна одна рука. Полный корпус на экране появляется в:

* «эхо» на камерах наблюдения: `staff`, `shadow`, `hero` (`world.ts: echoes`, `poseTape`) — сейчас идут по клипам Walk/Idle;
* будущих NPC и сущностях, которые приходят к игроку по коридору — это главный выигрыш: ходьба/бег с естественными разворотами, остановками, приседом.

Для самой игрока MotionBricks полезен косвенно: источник качественных клипов для качания руки с фонарём, походки у зеркал/в отражениях, кат-сцен.

## 5. Совместимость персонажа и ретаргетинг (измерено)

Наш персонаж: `public/assets/iso/alexei-10.glb`, MakeHuman, **53 кости в одном skin**, Y-up, +Z вперёд, левая сторона = +X, A-поза (руки вниз ~37°), клипы Idle/Walk/Run/CrouchIdle/CrouchWalk/Hold (Walk/Run — 1 с, цикл).
SOMA: 30 суставов модели; корень `Hips`; Y-up; Т-поза; позиции в метрах (BVH — в см).

| SOMA (модель) | Наша кость | Примечание |
|---|---|---|
| Hips, Spine1, Spine2, Chest | pelvis, spine_01, spine_02, spine_03 | 1:1 |
| Neck1 (+Neck2) | neck_01 | Neck2 свёрнут в neck_01 |
| Head | head | цель — вектор «голова → середина глаз» (в модели нет HeadEnd), наклон 28,6° вперёд заложен в карте |
| L/R Shoulder, Arm, ForeArm, Hand | clavicle, upperarm, lowerarm, hand | 1:1 |
| L/R Leg, Shin, Foot, ToeBase | thigh, calf, foot, ball | 1:1 (ball не двигается) |
| *HandThumbEnd, *HandMiddleEnd | — | у нас нет концевых костей; используются как цель направления кисти |
| Jaw, LeftEye, RightEye | — | не нужны (глаза — только для направления головы) |

* **22 сустава совпадают напрямую**, 4 маркера пальцев производные, **4 виртуальных/неиспользуемых** (Neck2, Jaw, глаза). Пальцы, шея-2 и стопа-носок остаются в нашей позе покоя / клипе Hold.
* Пропорции: ноги SOMA 0,855 м, наши 0,868 м → **масштаб 1,014**. Рост ≈ 1,78 м у обоих. Высота таза различается (SOMA `Hips` выше на 7,4 см — это положение узла, не рост); поэтому высота таза не копируется, а считается так, чтобы нижняя стопа клипа стояла на нашей высоте голеностопа (0,072 м).
* **Метод** (`tools/motionbricks/retarget.mjs`): «перенос кадров». Для каждой кости с обеих сторон строится кадр из направления кости и боковой оси тела; наша кость получает `W = F_src · F_rest⁻¹ · W_rest`. Не нужно знать оси/«roll» костей SOMA (BVH-ось по X, наша по Y, Blender→glTF-конверсия) и разницу T-/A-позы. Всё работает на позициях суставов, поэтому **один и тот же ретаргетер годится для BVH, JSON из Python и (позже) потока в браузере**.

Результаты на настоящем SOMA-клипе (стенд, см. §7), векторы от корня цепочки, см:

| | ходьба 1,26 м/с | бег 4,17 м/с |
|---|---|---|
| ступни, голень | 0,3–0,6 | 0,5–0,6 |
| кисти, предплечье | 3,7–4,8 | 3,2–3,7 |
| голова | 4,2 | 4,3 |
| грудь | 2,7 | 2,7 |
| голеностоп над землёй (цикл) | 8,4–28,6 см | 8,6–48,8 см |
| цикл | 32 кадра (1,07 с) | 18 кадров (0,6 с) |

Ноги совпадают с источником до 1 см, руки/голова — 3–5 см (причина: скручивание вдоль оси кости берётся от боковой оси тела, а не из источника; станет точным после загрузки покоя SOMA из USD). Визуально: ходьба и бег выглядят естественно (проверено в браузере: `tools/motionbricks/preview/index.html`).

**Известные ограничения v0 (честно):**
1. Скручивание предплечий/голени и поворот кисти упрощены (см. выше).
2. Скольжение стоп не измерено надёжно (метрика грубая); для финала нужен foot-IK по контактам стоп, которые модель выдаёт (4 канала).
3. Скорость клипа: бег-образец 4,17 м/с против нашего бега ~2,7 м/с → нужно масштабировать время (`timeScale`) или генерировать с нужной скоростью (в MotionBricks скорость задаётся целевыми позами — это штатно).

## 8. Лицензии (проверить до выпуска)

* Код репозитория — Apache 2.0; **модели (ONNX/checkpoints) — NVIDIA Open Model Agreement**: коммерческое использование и распространение разрешены «с условиями соглашения». **Полный текст соглашения я не читал** (в репозитории только ссылка) — прочитать до публикации сгенерированных клипов.
* **Образцы движений (`assets/motions`, BVH из Bones RigPlay 1) — NVIDIA Sample Data Evaluation License: «только для оценки и тестирования», распространение производных запрещено.** Это важно дважды:
  1. стенд-клипы в `tools/motionbricks/out` **нельзя коммитить и публиковать** (добавлено в `.gitignore`, в метаданных клипа стоит пометка);

* Текстуры CC0 и прочие уже в проекте не затрагиваются.

## 9. План реализации (по этапам, каждый можно остановить)

**Этап 0 — решение (сейчас).** Подтвердить установку окружения (~3 ГБ в `C:\Users\libde\motionbricks-lab`, изолированно) — см. §10.

**Этап 1 — запуск модели.** `setup.ps1` → `probe_gpu.py` (видит ли Warp GPU, импорт TensorRT, VRAM) → `probe_gpu.py --build` (сборка плана FP16 в 4 ГБ) → `generate_locomotion.py --gait walk --fp16` и `--gait run`. Критерий: клип 8 с сгенерирован, время одной генерации записано в `meta`.

**Этап 2 — ретаргет настоящего выхода.** `make-clip.mjs walk --soma out/walk.soma.json`, `verify.mjs`, просмотр. Критерий: ошибка ног ≤ 2 см, нет вращения головы/плеч «в обратную сторону», стопы не уходят под пол (грунтовка по самому низкому голеностопу).
Попутно: загрузить USD-скелет SOMA (`usd-core`) и взять покой SOMA → точное скручивание предплечий и кистей (убирает ограничение 1).

**Этап 3 — подключение к игре (за флагом, без смены управления).** Новые файлы: `public/assets/iso/gait-<n>.json` (новое имя — опубликованные файлы не заменяем), `src/iso/motionbricks.ts` (загрузчик клипа, только `THREE.AnimationClip.parse`). Правка `src/iso/actor.ts`: опционально подмешать клип как ещё один слой Walk/Run для NPC/эхо; для игрока **ничего не менять**. Критерий: при отсутствии файла поведение побайтно прежнее.

**Этап 4 — собственные цели-позы (выполнен технически, лицензия — решение владельца).** `export-hero-poses.mjs` снимает наши Walk/Run из `alexei-10.glb` (30 Гц, один цикл), `lab/own_targets.py` обратным «frame transfer» превращает их в локальные позы SOMA (направления костей совпадают точно, ноги ставятся на землю, 8 циклов с движением таза вперёд), `generate_locomotion.py --targets own` генерирует ходьбу и бег от них (генерация ~16–21 мс), `make-clip.mjs --soma out/own-<gait>.soma.json --name own-<gait> --own 1` ретаргетит назад на героя. Результат: ходьба 1,21 м/с (цикл 1,77 с), бег 1,95 м/с (цикл 0,8 с) — близко к игровым шагам 1,25 и 2,0 м; в игре подключено как `gait-walk-2.json` / `gait-run-2.json`. Образцы NVIDIA больше не участвуют. Остаётся лицензия самой модели (NVIDIA Open Model Agreement): краткая сводка условий — вывод модели можно использовать коммерчески, NVIDIA не заявляет прав на выход, при распространении нужны уведомления, есть пункт о возмещении убытков; полный текст сводкой не подтверждён — прочитать оригинал перед релизом.
